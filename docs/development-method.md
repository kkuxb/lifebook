# 本项目 Skill 开发方法

来源：FDE 开发套件 1.1.1 的项目摘要，可在客户明确要求后按项目调整；详细阶段指导通过已安装的 fde-skill-development 按需读取。不需要把套件整体复制进项目。

1. 定义业务闭环：使用者、触发、输入来源、输出、完成标准、质量底线、非目标与权限。已确认任务要求可代替尚无的正式 SOP。
2. 验证最不确定的工具/数据/权限依赖。先做最小探针，不提前建设整套平台。宿主专属能力以目标环境为准。
3. 选择职责：Agent 做开放式理解与判断；脚本做确定性重复动作。初始化、日常运行和发布分开。
4. 按影响选尺度：低风险局部小修直接修改验证；标准开发留下设计与计划，小型新建可在一份简报分两部分；复杂/高影响任务分开落盘。设计说明关键取舍、职责/数据流、风险、复杂度/效率/成本预算和验收；目标确认不代替关键设计确认。
5. 已确认设计直接写计划，已有有效计划继续实施。计划按可验证结果明确文件/资源、输入输出、依赖、动作、具体验证和完成/阻塞边界；自查覆盖、接口、可执行性、顺序/权限和范围。未知接口先探针，不猜后续调用。已有开发授权内自查后直接实施，普通工程计划不加审批。按小步验证；门禁保护真实损失，局部失败不扩大，不为预想异常堆状态、队列和恢复机制。
6. 尽早跑获授权的小规模真实闭环。复杂的新 Skill 可用独立执行者，只给任务、正式文件和允许边界；没有子 Agent 可换新会话/人工执行。
7. 按业务完成度、质量、权限副作用、异常、效率成本、复杂度、迁移体验复盘。只修真实问题；无阻断就收口，多轮不收敛则重看设计。
8. 验证最终包和目标环境，交付使用说明、版本、证据范围和维护边界。技术通过与用户业务验收分别记录。

效率优化先删无效工作，提前过滤，按需给证据，合并机械回合，减少无信息等待，达标即停。保留业务必需原文和证据，完整审计可落本地，不反复回传模型。

性能比较使用同口径输入/版本/起止点。业务、人工等待、监督测试分开计量；缓存输入已含在总输入内，费用需实际价格或账单。没有精确 Token 写不可用。

新需求、重要事实缺口和未授权副作用需确认；已有设计/授权不重复审批。全局套件不保存本项目状态，所有事实和产物留在本工作区。
